# Agent Note：独立 Minecraft 窗口与当前会话标注

状态：已实现

[English](2026-09-14-independent-game-window-current-session-annotation.md) | 中文

## 问题

自动并排陪伴布局会在 Minecraft 运行时改变 CraftCode 窗口，并移除普通对话页面的部分界面。标注完成也一直绑定到开始截图时的会话，而不是提交瞬间的当前会话。

## 决策

Minecraft 保持独立的顶层窗口。Windows 捕获提供方只发现经过校验的 HWND、观察可见／最小化状态并管理私有截图流，不会重新定位、调整大小、隐藏、最大化或改变 CraftCode 的边界、顶栏或后台节流。连接游戏后，renderer 仍挂载原有顶栏、侧栏、详情栏、对话和输入框。游戏 slot 只暴露游戏名称、被动状态／错误和标注入口。

标注请求保留操作编号、项目路径、启动时会话和已有标签，用于快捷键绑定、项目校验和初始编号。preload 只按操作编号转发完成事件。提交瞬间，`ui-layout` 解析当时的当前会话并调用其标注绑定。标注覆盖层期间可以切换会话；当前会话不可用或编号冲突时保持覆盖层和草稿打开，只有成功才关闭并重置覆盖层。

该设计替代自动并排陪伴布局及其重新定位／重连契约。原生窗口所有权仍在桌面主进程，会话所有权则在 renderer 的布局服务中于提交时解析。

## 验证

provider 单测和原生 fixture 覆盖发现、移动、最小化／恢复、切换、停止及游戏退出，确认 CraftCode 几何和可见性不变。布局和工作区测试确认连接游戏不会增加专注模式属性或陪伴控件。preload 契约和 renderer 测试覆盖按操作编号投递与原页面保持不变。

## 备选方案

保留陪伴布局可以继续自动排列窗口，但会违背原页面保持不变的要求。每次切换会话都取消覆盖层可以避免归属不明确，却无法满足提交时解析当前会话的需求。

## 后果

用户需要自行排列两个独立窗口。游戏区域除标注外保持被动；当前会话保存失败时覆盖层保持打开，用户可以修正会话后重试。
