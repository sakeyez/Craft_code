# Agent Note: 游戏与陪伴面板自动并排布局

Status: implemented

[English](2026-09-07-game-side-by-side-layout.md) | 中文

## Problem

宽大的 Minecraft 窗口旁配一个窄陪伴面板，可以同时留出游戏检查和对话空间。只移动 CraftCode 无法保证两个窗口都能放下，覆盖面板还可能遮挡游戏控件。

## Decision

Windows 桌面提供方将当前项目的游戏与陪伴面板安排为两个独立顶层窗口。本决策部分取代[游戏工作区标注](2026-09-02-game-workspace.zh.md)中的只观察定位方案；原生窗口所有权、样式、游戏直接输入和标注捕获仍由该记录说明。

首次可见窗口连续两次轮询稳定后执行布局。使用该显示器的可用工作区，四周和窗口间隔均为 8 DIP。CraftCode 占可分配宽度约 26%，限制在 360-520 DIP，同时为 Minecraft 至少保留 640x480 DIP。两窗高度均为工作区高度减 16 DIP。空间不足时保留独立窗口。普通最大化游戏窗口先还原，全屏窗口等待回到窗口模式。

游戏窗口连接后，renderer 进入专注模式，隐藏项目控件（顶部菜单、侧边栏和空会话项目选择器），同时保持对话挂载。断开或停止游戏会移除专注标记并恢复控件。

提供方在请求异步原生移动前重新验证 HWND、PID 和进程创建身份。Electron 负责物理屏幕坐标与 DIP 转换，可见窗口外框偏移用于计算 Windows 缩放边框。有界结果检查会停止失败的布局并允许显式重试。renderer IPC 只提供项目选择和重新定位命令。

游戏移动和缩放时同步陪伴面板右侧位置与高度，并保留手动宽度。右侧空间不足时暂停跟随，不移动或置顶面板。重新定位会重新安排两窗并恢复跟随。项目选择、重连和最小化／恢复均保留已经布局的游戏窗口。游戏退出时恢复 CraftCode 位置、最大化、最小尺寸、置顶和后台节流状态。

## Alternatives considered

**只观察定位。** 完全不移动游戏无法保证宽游戏窗口与窄面板的可预测布局。显式重新定位和一次自动布局限制了原生调整的次数。

**标注期间的临时覆盖。** 覆盖只用于一次性静帧标注事务，位于已验证的 Minecraft 客户区边界内；它冻结视觉但不挂起进程，结束后立即销毁并恢复并排布局。普通浏览和对话仍使用独立的并排窗口，避免持续遮挡游戏。

**第一版增加尺寸设置。** 固定默认值覆盖所需工作流，保留手动调整面板宽度即可提供控制能力，无需增加设置契约。

## Consequences

桌面获得可预测的布局，代价是允许调整已确认属于当前游戏的窗口尺寸。几何、所有权、超时、切换和原生最小化／恢复测试覆盖这一边界。真实 Minecraft 检查与窄面板检查仍然必要；布局测试通过不能证明恢复后页面空白的根因。
