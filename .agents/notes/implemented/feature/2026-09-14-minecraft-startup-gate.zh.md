# Agent Note：Fail-closed Minecraft 启动门禁

状态：已实现

English | [中文](2026-09-14-minecraft-startup-gate.md)

## 问题

编译或 Gradle build 成功并不能证明 Minecraft 能完成模组发现与初始化。直接启动损坏的客户端/服务器会把第一次失败暴露给用户。

## 决策

`run_mc_check` 增加 `startup` 目标，要求明确的 client/server 模式与用户批准。它按顺序运行静态资源校验、可选 datagen、`processResources`、`test` 和 `build`，第一处失败立即停止；随后才运行有界运行时探测。只有观察到保守的原版就绪标记（或在标记出现后因有界超时结束）才算通过；无标记的正常退出视为失败。模型必须分类失败阶段、基于证据做最小纠正，并重新运行完整门禁后才能展示游戏。

## 备选方案

**把 build 成功当作启动证明。** 否决，因为编译不会覆盖模组发现、元数据加载和运行时初始化。

**编辑后总是直接启动游戏。** 否决，因为这会把可预见的失败暴露给用户，也无法在启动边界前清晰区分环境与依赖问题。

## 后果

用户看到的是结构化的阻断结果，而不是立即失败的游戏窗口。运行时标记保持保守，若 loader 使用不同日志格式仍需项目级补充；门禁通过表示启动就绪证据，不保证后续玩法正确。
