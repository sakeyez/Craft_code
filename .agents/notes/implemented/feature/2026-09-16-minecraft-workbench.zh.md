# Agent Note: 宿主管理的 Minecraft 工作台

Status: implemented

[English](2026-09-16-minecraft-workbench.md) | 中文

## 问题

Minecraft 开发需要保留执行证据，并在 Gradle、模组元数据和测试安装间一致地修改依赖。桌面窗口句柄不能证明游戏就绪，编辑器保存也可能覆盖助手并发修改。

## 决策

[工作台宿主](../../../../packages/minecraft/mc-workbench/README.zh.md) 管理项目操作、记录事务的依赖修改、源码来源及带版本校验的文件访问。[客户端插件](../../../../packages/client/ui-mcmod-workbench/README.zh.md) 提供插槽并在本地保留草稿。用户通过现有会话消息主动发送片段前，日志不进入模型上下文。

[初始化决策](2026-09-14-minecraft-host-bootstrap.zh.md) 继续管理目录、暂存和首次构建发布；Java 准备与工作台共用。[独立游戏窗口决策](2026-09-14-independent-game-window-current-session-annotation.zh.md) 继续管理原生窗口识别和标注。这些记录所管理的机制并未完全被取代，因此保持活动状态。

项目导航与应用菜单共用一行，切换工具无需占用第二行标题栏。布局管理菜单、导航和末尾窗口控制插槽，桌面插件管理剩余可拖拽区域。独立插槽让浏览器导航不依赖 Electron，并保留已挂载页面的状态。

宿主网络服务按操作固定设置，避免代理变化让运行中的下载或构建混用策略。明确镜像映射和发布方校验保持产物身份；Java 使用子进程属性，不修改全局配置。PAC、SOCKS 和认证代理不会被静默转换。网络偏好不进入模型上下文。

显式客户端会话导航即使在当前会话标识不变时也会恢复对话，因此顶栏只需保留项目工具，草稿和运行日志仍会保留。

恢复点在被保护工具和依赖提交前失败即阻止操作，因为不完整备份无法保证安全恢复。内容哈希去重源码状态；带日志的恢复校验文件版本，不重置 Git。精确输入及产物哈希让过期验收与导出证据失效。API 查询进入普通工具日志；后台预览和轮询不进入模型上下文。

[独立开发决策](../architecture/2026-09-20-independent-minecraft-development.zh.md)定义项目环境、最小启动与准备语义。网络偏好通过应用设置访问。

## 考虑过的替代方案

**复制 ModMind 实现。** CraftCode 使用 AGPL-3.0-only 并保留上游 MIT 声明。此独立实现参考 ModMind 的流程，没有引入 ModMind 或 PCL 源码。精确版本安装使用固定的 MIT XMCL 包，而非 PCL 代码。

**每个界面控件自行管理进程。** 导航和重连会使日志与停止权限丢失。宿主管理让操作状态独立于窗口连接而持久存在。

**按编辑器快照覆盖文件。** 版本校验保留外部和助手修改，要求用户检查冲突后再重新载入。

## 影响

单项目适配器拒绝无法可靠修改的布局。未知兼容性和映射保持明确。依赖与源码缓存设有边界并以哈希标识。Java 语义编辑不在工作台范围内。独立本地测试实例共享已校验资源，按项目及运行侧隔离可变游戏状态。

文件系统和事务测试覆盖冲突与恢复。真实应用浏览器测试验证保留的中文日志、本地 Monaco、导航草稿和外部修改后的保存拒绝。这些检查不证明 Minecraft 客户端或服务端启动；真实 Gradle 构建和另行授权的运行验证保持独立证据。
