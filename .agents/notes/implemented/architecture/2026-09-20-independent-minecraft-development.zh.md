# Agent Note: 独立的 Minecraft 开发环境

Status: implemented

[English](2026-09-20-independent-minecraft-development.md) | 中文

## Problem

IDE 与助手可能选择不同 JDK、Gradle 缓存、仓库和启动检查。新建后的开发运行若使用另一个 Gradle User Home，已经完成的下载便无法复用。委托 IDEA 执行能够获取其实时设置，却让助手依赖已安装且打开项目的 IDE。

## Decision

工作台独立执行项目 Wrapper 任务。项目环境记录保留新建时的缓存位置、验证过的 JDK 路径及已发现任务。构建／环境指纹使派生选择失效，不删除 Gradle 缓存。开发启动执行发现的运行任务及其依赖，构建与静态检查保持独立。准备使用支持加载器的 JavaExec 依赖图与参数 provider，不执行启动动作；无法解析或自定义的运行输入保持未验证。

准备与构建复用兼容 Gradle daemon。游戏运行保留所属单次 daemon，因为进程树取消无法安全终止共享 daemon 下的游戏。模型执行保留原 shell 策略。重启不会自动启动游戏，EULA 独立接受，进程初始化、世界就绪与玩法通过分别记录。

产品不包含强制 IDEA 集成。其原有动机——读取实时 RunManager 设置而非猜测 XML——可供未来可选对照功能参考。重新引入需要明确产品需求、项目范围认证、脱敏环境摘要、幂等操作标识及真实 IDE 兼容性／运行证据。连接成功或插件编译不能证明执行一致，浏览器／模型也不能借 IDE 通道绕过批准。

本决策部分替代[工作台记录](../feature/2026-09-16-minecraft-workbench.zh.md)的启动前检查；其中的依赖事务、日志和编辑器归属仍然有效。

## Alternatives considered

- 强制 IDEA 能提供真实 IDE 执行，但不符合独立运行要求。
- 重建 IDEA XML 无法证明实时有效配置，Wrapper 执行也不需要它。
- 每次启动前运行 test/build/datagen 会增加失败路径，破坏有针对性的增量开发。
- 删除全部缓存或其他进程的锁会破坏有效工作；损坏的 Loom 元数据仅从验证过的本地数据修复，并保留损坏原文。

## Consequences

准备只证明输入可解析，不证明标题画面或玩法。自定义 JavaExec 动作及运行时联网仍可能需要额外内容。游戏启动仍承担独立 daemon 的开销。离线启动、全部加载器／版本组合及服务端 EULA 需要单独证据，组装测试不能代替真实验收。独立稳定性是验收目标，不代表已证明 IDE 设置完全相同。

## Verification

定向环境测试覆盖缓存连续性、指纹失效、损坏记录和有边界的元数据修复。生命周期测试覆盖取消／日志收尾、沙箱拒绝及没有额外 build/test 门禁的运行任务。真实验收记录与仓库检查分开保存。
