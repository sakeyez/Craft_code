# @deepseek-ai/dsh-client-ui-desktop-menu

[English](README.md) | 中文

基于共享 Web 外壳的 Electron 专用桌面菜单 UI。存在沙箱 preload 桥接时，本插件注册一个 `shell.overlay` 条目，把原生菜单动作转换成由 renderer 绑定的 observable，并以共享主题组件呈现项目设置、Git 输入与确认，以及命令反馈。在 Windows 和 Linux 上，本插件向 `shell.topbar` 注册项目、Git 和帮助菜单，向 `shell.window-controls` 注册三个 32px 窗口按钮及可拖拽区域。布局将项目导航放在两者之间，共用一行 40px 顶栏。菜单标签采用 14px 字号和 10px 横向内边距。按钮不会触发拖拽；Electron 会在入口对应的受限 renderer 坐标处打开所选原生子菜单。macOS 使用系统应用菜单和原生窗口边框，普通浏览器不会获得任何桌面条目。

preload 桥接只公开封闭的菜单、游戏进程和项目范围游戏状态订阅、固定的 `openMenu` 与当前项目请求、一个请求／响应式 `invokeProjectCommand` 方法，以及受限的标注操作。连接状态使用 `surfaceKind: 'external-window'`；Minecraft 始终是独立顶层窗口，HWND 和 Win32 细节只留在主进程。该插件通过 `ctx.layout` 转发游戏状态和标注操作，不提供重连或重新定位控件；组件既不订阅全局 window 事件，也不从命令完成结果推断捕获状态。主进程会校验弹出请求的发送者身份、菜单 id、相对内容区坐标、当前项目和项目命令种类。普通命令完成只有一个所有者：invoke 返回值；长期运行的 Minecraft 进程会通过专用游戏事件报告稍后的自行退出或失败。组件通过各自的注入面接收菜单呈现方式、工作区创建和命令调用，不读取 Cordis Context 或 Node API。Electron 主进程继续持有文件系统、进程和 HWND 权限，目录、构建产物与保存位置仍由操作系统原生对话框选择。

简短的成功和取消操作会在四秒后关闭，游戏正常退出也使用同样的短提示。游戏失败以及其他带 stdout 或 stderr 的结果会保留到用户关闭，有界进程输出通过可展开的详情区呈现。所有输入均为受控状态，弹窗操作支持键盘，状态指示同时使用文字和状态图形，不只依赖颜色。

桥接层通过 `ctx.layout` 转发带操作身份的标注快捷键订阅，包括注册错误和释放操作。原生句柄和捕获流权限保留在主进程。

## 模型体验

### 项目设置

#### 模型看到的内容

保存后，后续请求会通过所属 agent-loop 提示词集成加入 `.dsh/project.yaml` 中配置的 `systemPrompt` 与前置模组路径；菜单交互、Git 命令和通知状态不会进入模型上下文。

#### Token 影响

配置文本与前置路径会为后续每次请求增加对应的提示词 token；桌面 UI 本身不增加 token。

#### KV Cache 影响

修改任一配置字段都会改变后续请求的提示词前缀，并可能降低提供方侧缓存复用；仅 UI 交互不影响缓存。

## 已知限制与暂缓事项

- **需要 Electron preload**——浏览器标签页不会获得桌面菜单条目或其中的特权命令。
- **原生子菜单和对话框遵循操作系统样式**——子菜单行、目录对话框与 JAR 保存对话框不会继承 Web 主题 token。
- **游戏启动遵循根 Gradle 任务**——桌面命令只接受一个未限定的 `runClient` 或 `runGame`；它不会在有限定的多项目任务中代选，也不会打开已安装的启动器。
- **只显示一个命令结果**——新命令会替换先前提示；进程输出仍受 Electron 命令运行器的长度限制。
